# CEREBRO ETL 기능 시연 시나리오 (20분)

발표 자료 `CEREBRO_ETL_시연_20261001.pptx` 와 짝이 되는 진행 계획이다. **화면 경로 · 보여줄 것 · 시간 배분 · 막혔을 때의 대안**을 담았다.
읽어 가며 말할 문장은 [시연 대본](2026-10-01-demo-script.md)에 따로 있다.

시연 환경은 **MSA 서버**를 기준으로 한다(정형 3종 작업물이 거기에 있다).

---

## 0. 전체 흐름과 시간

| 순서 | 내용 | 시간 | 누적 |
|---|---|---|---|
| 1 | PPT 발표 (5장) | 3분 | 3분 |
| 2 | 메인 화면 설명 | 2분 | 5분 |
| 3 | 추가된 기능 — UI/UX · AI 어시스턴트 · 카카오 알림톡 | 4분 | 9분 |
| 4 | **ETL 생성 위자드 — DB → DB job 생성** | 3분 | 12분 |
| 5 | 정형 적재 3종 실행 | 4분 | 16분 |
| 6 | 비정형 적재 | 1분 30초 | 17분 30초 |
| 7 | 워크플로우 순차 · 병렬 | 2분 30초 | 20분 |

**시간이 밀리면 줄일 순서** — ① UI/UX(말로 대체) ② 정형 3종 중 HTTP · API(구조만 보여주고 실행 생략)
③ 비정형. **끝까지 지킬 것은 AI 어시스턴트 · ETL 생성 위자드 · 워크플로우 실행** 세 가지다.

> **이어 붙이면 좋은 흐름** — 4번에서 만든 job 을 5번의 DB → DB 실행 대상으로 그대로 쓰면
> "만들고 → 바로 돌리고 → 결과 확인"이 한 줄로 이어지고 1분 정도 아낄 수 있다.
> 다만 **새로 만든 job 이 첫 실행에서 실패할 위험**이 있으므로, 안전하게 가려면 실행은 미리 검증해 둔 MSA 작업물로 한다.

## 1. PPT 발표 — 3분

5장을 빠르게 넘긴다. 슬라이드마다 발표자 노트가 들어 있다.

- **1장 개요** — "수집부터 스케줄링까지 한 화면에서" 한 줄로 끝낸다.
- **2장 메인 화면** — **WEB BASED** 를 반드시 짚는다.
- **3장 시연 내용** — 왼쪽(추가 기능) · 오른쪽(실제 돌려 볼 작업)을 가리키며 예고한다.
- **4장 향후 과제** — 설치 가이드 · 사용자 가이드 · 교육 동영상.
- **5장 시연 시작** — 타임라인을 읽고 브라우저로 전환한다.

---

## 2. 메인 화면 설명 — 2분

**경로** 브라우저 → 로그인 → `대시보드`

1. 주소창을 한 번 짚는다 — "**WEB BASED** 입니다. 설치본이 없습니다."
2. 대시보드 — 전체 현황, 조치 대기열, 최근 실행 결과.
3. 상단 메뉴를 좌에서 우로 훑는다: **대시보드 / 워크플로우 / ETL / CDC / 설정**.
4. "메뉴는 로그인한 계정의 역할에 따라 달라집니다" — `설정 > 역할 및 권한` 을 1초만 보여준다.

## 3. 추가된 기능 — 4분

### 3-1. UI / UX 정비 (30초)

ETL 관리 → 워크플로우 관리 → CDC 관리를 차례로 열어 **트리 · 표 · 속성창 모양이 같다**는 점만 짚는다.

### 3-2. AI 어시스턴트 — 속성 (1분 30초) ★

**경로** `ETL` → `관리` → 트리에서 job 선택 → 우측 속성창 **[AI 어시스턴트]** 탭

- 탭을 열면 **대상 요약이 먼저 나온다**(질문 전에 이 job 이 무슨 일을 하는지 설명).
- 질문 하나를 직접 친다: `이 작업이 어떤 테이블을 어떻게 적재하는지 설명해줘`

### 3-3. AI 어시스턴트 — 로그 해석 (1분 30초) ★

**경로** `ETL` → `로그` → 실패 건 **[로그]** → 실패 창의 **[GPT 해석]**

- 원문 오류를 먼저 보여준 뒤 해석 버튼을 누른다.
- 결과는 **원인 추정 / 확인할 것 / 조치 방법** 형식.

### 3-4. 카카오 알림톡 (30초)

**경로** `설정` → `알림/발송` → `발송 채널`

- 카카오 행의 **[발송]** 을 누르고 **휴대폰을 들어 보인다**.
- 물음표의 **설정 방법 안내**를 1초 보여주면 좋다.

## 4. ETL 생성 위자드 — DB → DB job 생성 — 3분 ★

**경로** `ETL` → `생성`

위자드는 **5단계**다. 단계 표시줄이 위에 떠 있으므로, 넘어갈 때마다 어디까지 왔는지 짚어 준다.

| 단계 | 화면 | 시연에서 할 일 |
|---|---|---|
| 1 | **유형 선택** | 4종(DB → DB 적재 · 파일 적재 · HTTP 수집 · 비정형 전송)을 보여주고 **DB → DB 적재** 선택 |
| 2 | **기본 정보** | 작업명 입력(예: `DEMO_ORDER_LOAD`), 상위 그룹 선택, 설명 한 줄 |
| 3 | **연결 설정** | 소스 · 타깃 연결정보를 **목록에서 고르고**, 소스 테이블 선택 |
| 4 | **적재 쿼리** | 적재 방식 선택(**TRUNCATE** 권장 — 반복 시연에 안전), 추출 쿼리 확인 |
| 5 | **컬럼 매핑** | 소스 ↔ 타깃 컬럼이 자동으로 맞춰진 것을 보여주고 **생성** |

**강조할 점**

- "SQL 을 직접 짜거나 NiFi 화면에 들어갈 일이 없습니다. **고르기만 하면 됩니다.**"
- 연결정보는 `설정 → 연결정보` 에 등록해 둔 것을 **재사용**한다(접속 정보를 매번 입력하지 않는다).
- 컬럼 매핑은 **이름이 같은 컬럼을 자동으로** 맞춰 준다. 다른 것만 손으로 고친다.

**생성 직후** `ETL` → `관리` 트리에서 방금 만든 job 이 올라와 있는 것을 보여준다. 여기서 5번으로 넘어간다.

> **준비** 작업명은 미리 정해 두고, **중복되지 않는 이름**인지 확인해 둔다.
> 상위 그룹 · 연결정보 · 소스 테이블도 **무엇을 고를지 미리 정해 두어야** 화면에서 헤매지 않는다.

---

## 5. 정형 데이터 적재 — 4분

각 건은 **① 구조 보여주기 → ② 실행 → ③ 결과 확인** 순서로 동일하게 간다.

### 5-1. DB → DB (2분)

**경로** `ETL` → `관리` → 해당 job 선택

1. 속성창에서 소스 · 타깃 테이블과 적재 방식 확인.
2. 실행 → `ETL` → `로그` 에서 **적재 건수**와 **성공** 확인.

### 5-2. HTTP 수집 (1분)

같은 순서. "외부에서 HTTP 로 받은 데이터를 그대로 테이블에 적재합니다."

### 5-3. API 연계 — 온톨로지 (1분)

같은 순서. 현재 **작업 중인 영역**임을 밝히고 구조 위주로 보여준다.

> **진행자 메모** 세 건 모두 **미리 한 번 돌려 두고**, 시연에서는 다시 실행한다.
> 오래 걸리는 건은 결과 확인을 **먼저 돌려 둔 이력**으로 대체한다.

---

## 6. 비정형 데이터 적재 — 1분 30초

**대상** 음성 파일 수집 · 적재 (※ **job 구성 필요** — 준비 항목 참고)

1. 위자드의 **비정형 전송** 유형으로 만들었음을 밝힌다(4번에서 본 화면과 연결).
2. 관리 화면에서 구조를 보여주고 실행한다.
3. 적재 결과(건수 또는 저장 위치)를 확인한다.

---

## 7. 워크플로우 스케줄링 — 2분 30초 ★

**경로** `워크플로우` → `관리` → 시연용 워크플로우 **[수정]**

1. **구조 설명** — 순차 구간과 병렬 구간을 짚는다.
2. **스케줄** — 속성창의 스케줄 칸(크론을 한국어로 풀어 표시).
3. **실행** — 수동 실행 → `워크플로우` → `로그` 로 이동.
4. **결과** — 작업별 상태가 순서대로 켜지고, 병렬 구간이 동시에 도는 것을 보여준다.

## 준비 체크리스트

### 시연 전날

- [ ] **비정형(음성) job 구성** — 유일하게 아직 만들어지지 않은 항목. 가장 먼저 처리한다.
- [ ] **ETL 위자드 입력값 확정** — 작업명 · 상위 그룹 · 소스/타깃 연결정보 · 소스 테이블 · 적재 방식.
      같은 이름으로 **연습 생성을 한 번 해 보고 지운다**(연결정보 목록에 원하는 항목이 뜨는지 확인).
- [ ] 정형 3종(DB→DB · HTTP · API) 각각 **한 번씩 성공 실행**해 두기.
- [ ] 시연용 워크플로우 준비 — **순차 + 병렬이 한눈에 보이는 모양**, 실행 시간 1~2분 안쪽.
- [ ] AI 어시스턴트용 **실패 로그 1건** 확보.
- [ ] 화면 캡처 백업 — 각 단계의 성공 화면을 미리 캡처.

### 시연 당일 아침

- [ ] 컨테이너 상태 확인 — 전부 `healthy` 인지. 내려간 것이 있으면 복구 후 시작.
- [ ] **카카오 토큰 갱신** — 액세스 토큰이 6시간마다 만료된다. 갱신 후 **[발송]** 으로 1건 확인.
- [ ] **GPT 연결 테스트** — `설정` → `GPT` → `관리` 에서 **[테스트]** 성공 확인.
      (크레딧이 떨어지면 AI 어시스턴트가 통째로 막힌다. 반드시 당일 확인.)
- [ ] 브라우저 준비 — 로그인해 두고 확대 비율을 발표 화면에 맞춘다. 탭은 하나만.

## 막혔을 때

| 상황 | 대처 |
|---|---|
| AI 어시스턴트가 응답하지 않음 | "지금 외부 연결이 막혀 있다"고 짧게 말하고 캡처로 설명. 원인은 대개 **GPT 크레딧 또는 토큰 만료**. |
| 카카오 알림이 안 옴 | 토큰 만료가 대부분. 이메일 채널 **[발송]** 으로 대체해 "채널만 다를 뿐 같은 구조"로 설명. |
| **위자드 생성이 실패함** | 오류 메시지를 그대로 읽고 **이름 중복 · 연결정보 미선택**부터 확인. 그래도 안 되면 "이미 만들어 둔 같은 구성"으로 넘어간다(미리 하나 만들어 둘 것). |
| job 실행이 오래 걸림 | 실행만 걸어 두고 **미리 돌려 둔 이력**으로 설명한 뒤, 끝나면 돌아와 확인. |
| 실행 실패 | 당황하지 말고 **AI 어시스턴트의 로그 해석**으로 넘어간다. 실패가 오히려 시연 소재가 된다. |
| 화면이 느림 | 새로고침보다 **다른 메뉴로 이동 후 복귀**가 빠르다. |
