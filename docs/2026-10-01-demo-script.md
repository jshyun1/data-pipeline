# CEREBRO ETL 시연 대본 (20분)

**그대로 읽어도 되는 문장**으로 적었다. `〔 〕` 는 말하지 않고 하는 동작, **굵은 글씨**는 꼭 짚고 넘어갈 말이다.
진행 순서·준비물은 [시연 시나리오](2026-10-01-demo-scenario.md)에 있다.

## 1. PPT 발표 — 3분

### 1장 · 개요

> 안녕하십니까. 오늘은 저희가 만들고 있는 데이터 파이프라인 플랫폼 **CEREBRO ETL** 을 보여드리겠습니다.
>
> 한마디로 말씀드리면, **데이터를 가져오고 쌓고 돌리는 일을 한 화면에서 끝내는 도구**입니다.
> 오늘은 지난번 이후 새로 올라간 기능 위주로, 20분 동안 실제 화면에서 직접 돌려 보겠습니다.

〔2장으로 넘김〕

### 2장 · 메인 화면

> 가장 먼저 말씀드릴 것은 **WEB BASED** 라는 점입니다.
>
> 설치할 프로그램이 없습니다. 브라우저 주소만 알면 어느 자리에서든 같은 화면으로 쓰실 수 있습니다.
> 설계하고, 실행하고, 지켜보는 일이 모두 이 안에 있어서 도구를 여러 개 띄워 놓고 맞춰 볼 필요가 없습니다.
>
> 메뉴는 크게 다섯입니다. 대시보드, 워크플로우, ETL, CDC, 그리고 설정입니다.

### 3장 · 시연 내용

> 왼쪽이 이번에 새로 들어간 기능이고, 오른쪽이 오늘 실제로 돌려 볼 작업입니다.
>
> 새 기능은 화면 전반을 정비한 것, **AI 어시스턴트**, 워크플로우 생성·관리, ETL 생성 위자드, 그리고 카카오 알림톡입니다.
> 작업은 정형 데이터 세 가지와 비정형 데이터 하나, 그리고 워크플로우 스케줄링까지 보여드리겠습니다.

### 4장 · 향후 과제

> 기능은 이만큼 올라왔고, 이제 **누구나 설치하고 쓸 수 있게 만드는 일**이 남았습니다.
>
> 설치 가이드와 사용자 가이드를 준비하고 있고, 글로 설명하기 어려운 조작은 짧은 교육 영상으로 보완할 계획입니다.

### 5장 · 시연 시작

> 그럼 지금부터 20분 동안 이 순서로 보여드리겠습니다. 보시다가 궁금한 점은 중간에 말씀해 주셔도 됩니다.

〔브라우저로 전환〕

## 2. 메인 화면 — 2분

〔로그인 후 대시보드〕

> 지금 보시는 게 접속하면 처음 뜨는 **대시보드**입니다. 〔주소창을 가리키며〕 보시는 것처럼 **브라우저 주소 하나**입니다.
> 따로 설치한 프로그램이 아닙니다.
>
> 여기서 전체 현황을 봅니다. 오늘 무엇이 돌았는지, 실패한 게 있는지, 손봐야 할 일이 있는지가 한 화면에 모여 있습니다.

〔상단 메뉴를 왼쪽에서 오른쪽으로 짚으며〕

> 위쪽 메뉴를 보시면 — **워크플로우**는 여러 작업을 묶어서 순서대로 돌리는 곳이고,
> **ETL** 은 데이터를 가져와 쌓는 작업을 만들고 관리하는 곳입니다.
> **CDC** 는 원본이 바뀔 때마다 변경분만 따라가는 기능이고, **설정**에는 알림이나 연결 정보, 계정 권한이 들어 있습니다.

〔설정 > 역할 및 권한 을 잠깐 열며〕

> 그리고 이 메뉴는 **로그인한 사람이 누구냐에 따라 달라집니다.** 조회만 가능한 분에게는 만들기 버튼이 아예 보이지 않습니다.

## 3. 추가된 기능 — 4분

### 3-1. UI / UX (30초)

〔ETL 관리 → 워크플로우 관리 → CDC 관리를 차례로 열며〕

> 화면 전체를 한 번 정비했습니다. 보시면 ETL이든 워크플로우든 CDC든 **왼쪽 트리, 가운데 목록, 오른쪽 속성**으로 모양이 같습니다.
> 한 화면에 익숙해지시면 나머지는 따로 배우실 게 없습니다.

### 3-2. AI 어시스턴트 — 속성 (1분 30초)

〔ETL → 관리 → job 하나 선택 → 오른쪽 속성창의 AI 어시스턴트 탭〕

> 이번에 새로 들어간 기능입니다. 작업 하나를 고르고 오른쪽 **AI 어시스턴트** 탭을 열어 보겠습니다.
>
> 〔탭을 열고 잠깐 기다림〕 보시는 것처럼 **묻기도 전에 이 작업이 무슨 일을 하는지 먼저 설명**해 줍니다.
> 어느 테이블에서 가져와서 어디에 쌓는지, 최근에 어떻게 돌았는지까지요.

〔질문 입력〕

> 직접 물어볼 수도 있습니다. "이 작업이 어떤 테이블을 어떻게 적재하는지 설명해줘" 라고 쳐 보겠습니다.
>
> 〔답변이 나오면〕 이 작업을 만든 담당자가 아니어도, 인수인계를 못 받았어도 **무슨 일을 하는 작업인지 바로 파악**할 수 있습니다.

### 3-3. AI 어시스턴트 — 로그 해석 (1분 30초)

〔ETL → 로그 → 실패 건의 로그 버튼〕

> 더 쓸모 있는 건 이쪽입니다. 작업이 실패했을 때를 보겠습니다.
>
> 〔오류 원문을 보여주며〕 지금 보시는 게 실제 오류 원문입니다. 솔직히 이걸 보고 바로 원인을 아시는 분은 많지 않습니다.

〔GPT 해석 버튼〕

> 여기서 **GPT 해석**을 눌러 보겠습니다.
>
> 〔결과가 나오면〕 **원인이 무엇인지, 무엇을 먼저 확인해야 하는지, 어떻게 조치하면 되는지**를 정리해 줍니다.
> 담당자가 로그를 뒤지는 시간을 줄이려고 넣은 기능입니다.

### 3-4. 카카오 알림톡 (30초)

〔설정 → 알림/발송 → 발송 채널〕

> 마지막으로 알림입니다. 이메일과 문자에 더해 **카카오 알림톡**을 붙였습니다.
>
> 지금 바로 한 건 보내 보겠습니다. 〔발송 버튼을 누르고 휴대폰을 들어 보이며〕 이렇게 담당자 휴대폰으로 바로 갑니다.
> 위험 등급 알림만 나가도록 돼 있어서, 사소한 경고까지 울려서 결국 무시하게 되는 일은 없습니다.

## 4. ETL 생성 위자드 — DB → DB 만들기 — 3분

〔ETL → 생성〕

> 이제 작업을 **직접 하나 만들어** 보겠습니다. 예전에는 이런 걸 만들려면 NiFi 화면에 들어가서 프로세서를 하나하나 놓아야 했는데,
> 지금은 **다섯 단계만 따라가면** 됩니다.

### 1단계 · 유형 선택

> 먼저 어떤 종류인지 고릅니다. **DB에서 DB로 옮기기**, 파일 적재, HTTP 수집, 그리고 음성 같은 **비정형 전송**까지 네 가지가 있습니다.
> 오늘은 가장 많이 쓰시는 **DB → DB 적재**로 하겠습니다.

### 2단계 · 기본 정보

> 작업 이름과 어느 그룹에 넣을지를 정합니다. 〔입력하며〕 이름은 `DEMO_ORDER_LOAD` 로 하겠습니다.

### 3단계 · 연결 설정

> 여기가 핵심입니다. **접속 정보를 매번 입력하지 않습니다.**
> 설정에 등록해 둔 연결 정보를 **목록에서 고르기만** 하면 됩니다. 가져올 쪽과 넣을 쪽을 각각 고르고,
>
> 〔소스 테이블 선택〕 가져올 테이블을 고릅니다. 보시는 것처럼 **실제 DB를 읽어 와서** 테이블 목록을 보여줍니다.

### 4단계 · 적재 쿼리

> 어떻게 쌓을지 정합니다. 기존 데이터를 비우고 새로 넣을지, 그냥 덧붙일지, 키가 같으면 갱신할지를 고릅니다.
> 오늘은 비우고 새로 넣는 방식으로 하겠습니다. **SQL을 직접 쓰지 않아도** 아래에 쿼리가 만들어집니다.

### 5단계 · 컬럼 매핑

> 마지막으로 컬럼을 맞춥니다. 〔화면을 가리키며〕 **이름이 같은 컬럼은 자동으로 연결**되어 있습니다.
> 다른 것만 손으로 바꿔 주시면 됩니다.

〔생성 버튼〕

> 생성하겠습니다. 〔완료되면 ETL → 관리로 이동〕 보시면 방금 만든 작업이 트리에 올라와 있습니다.
> **여기까지 3분이 안 걸렸습니다.**

## 5. 정형 데이터 적재 — 4분

### 5-1. DB → DB (2분)

〔ETL → 관리 → 해당 job〕

> 그럼 실제로 돌려 보겠습니다. 이 작업은 원본 DB의 테이블을 그대로 가져와 쌓는 작업입니다.
> 〔속성창을 가리키며〕 어디서 가져와서 어디에 넣는지, 어떤 방식으로 쌓는지가 여기 나와 있습니다.

〔실행 → ETL → 로그〕

> 실행하고 로그로 가 보겠습니다. 〔결과를 가리키며〕 **몇 건이 들어갔는지까지** 기록에 남습니다.

### 5-2. HTTP 수집 (1분)

> 다음은 외부에서 HTTP로 받아 오는 작업입니다. 구조는 방금과 같고, 가져오는 방법만 다릅니다.
> 〔실행 후 결과 확인〕

### 5-3. API 연계 — 온톨로지 (1분)

> 마지막은 API로 연계하는 작업입니다. 이건 **지금 작업 중인 영역**이라 구조 위주로 보여드리겠습니다.

## 6. 비정형 데이터 적재 — 1분 30초

> 지금까지는 표 형태의 정형 데이터였습니다. **음성 파일**도 같은 방식으로 다룰 수 있습니다.
> 조금 전 위자드에서 보신 **비정형 전송** 유형으로 만든 작업입니다.
>
> 〔실행 후 결과 확인〕 이렇게 파일을 가져와 쌓는 것까지 같은 화면에서 처리됩니다.

## 7. 워크플로우 스케줄링 — 2분 30초

〔워크플로우 → 관리 → 시연용 워크플로우 수정〕

> 마지막입니다. 지금까지는 작업 하나씩이었는데, 실제 운영에서는 **여러 작업을 순서대로** 돌려야 합니다.
>
> 〔캔버스를 가리키며〕 여기가 그 순서를 그리는 화면입니다.
> 이쪽은 **앞 작업이 끝나야 다음이 도는** 구간이고, 이쪽은 **동시에 도는** 구간입니다.
> 보시는 그대로 선을 이으면 그 순서대로 돌아갑니다.

〔스케줄 칸을 가리키며〕

> 그리고 여기에 시간을 넣어 두면 정해진 때에 자동으로 돕니다. 사람이 누르지 않아도 됩니다.

〔실행 → 워크플로우 → 로그〕

> 지금 한 번 돌려 보겠습니다. 〔로그 화면〕 보시면 작업이 **순서대로 켜지고**, 병렬로 둔 구간은 **동시에 도는 것**이 보입니다.
